## Protocol and dependency boundary

The source review is pinned to Stellar Core `05c6328c13b595c52b6ad1ecd1e69cd9b2a582d4`. The crate is locked to `stellar-xdr` 28.0.1 and Rust 1.97.1. The Core pin documents semantics; the XDR crate supplies generated types; tests cover the implemented operation subset. They are different forms of evidence. A newer Core or XDR release needs an explicit compatibility review before support is claimed.

Offline snapshots, live ledger headers, and stored captures are checked against one policy in `src/protocol.rs`. Versions 18 to 29 are evaluated. Versions below 18 and above 29 are refused as `UNSUPPORTED`. The upper bound exists because the pinned XDR decoder cannot parse protocol 30 ledger headers. The range is a source-review boundary. A separate live `getLatestLedger` response on 2026-10-31 reported protocol 29 at ledger 5490831; the CLI's immediately preceding capture was ledger 5490828, and the separate response is not that capture's header. See the [dated observation](../research/testnet-live-observation-2026-10-31.md) and [protocol support decision](../research/protocol-support-decision.md). The v1.0.0 release itself only enforces the lower bound. [Compatibility research](../research/compatibility-matrix.md) preserves the original source-review details.
